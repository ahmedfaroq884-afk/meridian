Perform a security audit and fix issues you can verify. Do not claim the website is impossible to hack.

   - Never put Supabase secret keys, legacy service-role keys, passwords, private tokens, or other server secrets in React components, browser JavaScript, HTML, public files, Git, or production build output.

2. **Supabase database security**

   - Only authenticated, explicitly authorized administrators may read or manage leads, content, settings, and private analytics.
   - Do not trust a hidden admin page, client-side checks, URL secrecy, or localStorage as authorization.

   - Add reasonable validation, input length limits, spam protection, and rate limiting where practical. Do not rely on frontend validation alone.

3. **Website hardening**
   - Check for XSS, unsafe HTML rendering, injection risks, insecure redirects, exposed debug information, and vulnerable dependencies.
   - Use appropriate Content Security Policy and other security headers where compatible with the website and its third-party integrations.
   - Avoid logging personal data. Collect only information needed for the lead funnel.
